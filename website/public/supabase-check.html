Supabase connection check

Diagnoses the website's Supabase connection without reading a single row. Paste the project URL and the anon key; the request is made by this browser, and neither value is stored, logged or sent anywhere except to your own Supabase project.

credentials

  • One request only: HEAD /rest/v1/records?select=* with Prefer: count=exact. A HEAD response has no body, so no record ever travels — only a status and a row count.
  • The anon key is public by design: it already ships in the browser bundle of the deployed site. What a visitor may read is decided by Row Level Security, not by keeping this key secret.
  • A service_role key is refused before any request is sent — it bypasses RLS and must never be handled in a browser.
  • Nothing here is persisted: no cookie, no storage, no server request. Reloading the page forgets both fields.
  • This page is a development diagnostic. The production Content-Security-Policy allows connections to this origin only, so it works in npm run dev and is blocked on the deployed site.
