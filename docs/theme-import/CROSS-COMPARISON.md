## Architecture choices

1. `ThemePipeline` remains the app-facing orchestration path. Host Settings switches update the imported engine; imported Studio selection is reflected back to host config/pipeline. The engines do not independently initiate competing app resource rebuilds.
2. The imported engine owns one appended `Application.Resources` package slot and only publishes translated, type-checked compatibility keys into the ERP root dictionary.
3. App/ERP startup, business modules, and current Settings navigation remain intact. Imported runtime initialization is guarded; initialization failure is logged and leaves the pre-existing ERP theme active.
4. The remote standalone `App.xaml`/`MainWindow.xaml` are intentionally not used. All remote production theme source/XAML under `Theme/` and Studio source under `step1.ThemeStudio/` are included via WPF SDK defaults; test `.cs` is excluded from the shipping app.
