## Cross-stage conversion requirements

1. **One authoritative document state.** Guided Mode and Full Workspace Mode must read/write one typed workspace store and the same revision. Full Workspace Mode changes navigation/density only; it must not fork a second draft, duplicate calculations, or lose progressive disclosure state.
2. **Persistent state at step boundaries.** Persist the WPF document snapshot’s customer-safe fields plus internal workspace state with schema version, stable IDs, revisions, optimistic concurrency and idempotent autosave. Draft persistence is not customer sharing/issuance. Restore should land at the last valid stage and rehydrate derived state from saved inputs.
3. **WPF is the calculation authority.** Use a single auditable decimal-domain calculation layer and server-side recomputation on save/issue. Browser calculations are previews. Keep per-formula precision/rounding explicit. Tests must compare WPF-source fixtures against both server and browser outputs.
4. **Pin the selected baseline.** Golden fixtures and conversion contracts target ADV `main` at `d862436c125c5a83ac86bdef9ccef34c587408b3`; record v2.0.15 release differences as explicit compatibility cases. Do not silently blend behavior from another WPF line.
5. **Customer/internal projection boundary.** Customer quote records may include agreed selling prices, VAT/discount and terms; they must not contain internal purchase price, utilization, margin, buy-sheet/wastage values, stock balances, sheet allocations, internal notes, or Step 9 exports. The internal Sheets page reads a staff-only projection and can never be rendered by the customer document builder.
6. **One continuous workflow.** Keep the guided stepper, resumable progress, always-visible document identity/status, inline validation, clear next/back actions, progressive disclosure and interruption-safe save. Full Workspace Mode is an alternate arrangement of the same controls/state, not a different product path.
7. **Visual gate.** Prototype complete, genuinely distinct Industrial Bento and Futuristic Neon experiences using the same state/interaction contract. Both must preserve contrast, focus, keyboard, reduced-motion and responsive behavior. Obtain explicit user approval after showing both before broad visual replacement; backend and calculation work may proceed in parallel.
