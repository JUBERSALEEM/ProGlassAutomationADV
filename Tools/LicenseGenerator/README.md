Vendor-side **offline activation** utility for the redesigned ProGlass licensing model.

## Security posture

This generator no longer embeds a production private key in source.

Instead it loads an **operator-held external key file** (`.pgkey`) that contains:

- `keyId`
- public key
- private key
- algorithm metadata
- purpose metadata

That key file must live **outside Git** and **outside customer machines**.

## What it generates

- customer-facing **activation request** is generated by the app
- vendor imports that request into the generator
- generator signs a **structured offline activation response JSON**
- customer imports that signed response into the app

## Current file roles

- activation request: `.pgrequest`
- signed activation response: `.lic`
- issuer key file: `.pgkey`

## App compatibility

The current app build trusts only the embedded public-key ring compiled into the app.

That means:

- loading a random new `.pgkey` file is useful for test / future rotation work
- but a response generated from it will only activate in the app **after** its public key is added to the app trust ring and a new build is released

For real production use, the vendor must load the external private key whose **public half already matches the app's trusted production key**.

## Intended secure workflow

1. Customer opens **Settings → License**.
2. Customer enters the vendor license reference.
3. Customer exports an activation request file.
4. Vendor opens the generator.
5. Vendor loads the external `.pgkey` issuer file.
6. Vendor imports the customer's activation request.
7. Vendor selects edition, features, expiry and policy.
8. Vendor generates the signed activation response `.lic`.
9. Customer imports the response in the app.
10. App verifies signature, keyId, product, install binding, machine binding, nonce and dates before activating.

## Important limitations

- This is still an **offline desktop licensing** model, not an unbreakable DRM system.
- The customer controls the machine, so determined binary patching remains theoretically possible.
- The goal is stronger authenticity, harder forgery, safer local protection and cleaner operational key custody.
